| `antigravity` (RSI-Exam) | `Antigravity` | RSI-Exam's setup table says **"Antigravity CLI"** |

So the page had three spellings of the Grok harness (`Grok`, `grok-build`, `Grok Build`) and two of Muse Code, and two
of the new labels were neither the board's own token nor the write-up's name — the comment justified `musecode` with
"no source capitalises it", which our own catalog contradicts. On a model page a row labelled just **"Grok"** also
reads as the *model* Grok rather than as xAI's CLI.

Fixed in `lib/benchmark-matrix.mjs`: `musecode → Muse Code`, `grok → Grok Build`, `grok-build → Grok Build`,
`antigravity → Antigravity CLI`, with the comment restated so every label names the source that publishes it. The
change is display-only — cohort tokens, row ids, joins and values are untouched — and `test/rsi-exam.test.mjs` now
pins all four labels plus an unlisted one (`proximus`) that must stay as its source spells it.

## Open item this gate did not fix

**`reviewed_at` in the identity map is a hardcoded constant, so new joins claim a review date that predates them.**
`ops/benchmark-table-2026-09-15/build-identity-map.mjs:99` writes `reviewed_at: '2026-09-16'` literally, and
`scripts/ingest-benchmark-scores.mjs:197` stamps every joined observation with
`Reviewed identity map ${identityMap.reviewed_at}`. So all 38 entries added today — the 18 Toolathlon joins, the 11
RSI-Exam joins and the 9 Vals gap-fills — ship user-visible provenance reading *"Reviewed identity map 2026-09-16"*,
four days before they existed; the same is true of everything added on 17–19 September. The sibling artifact
`ops/benchmark-table-2026-09-15/identity-map-review.json` does carry a live `generated_at`, so the process has the
right timestamp and only the map's own field is stale.

This gate did **not** change it. Making the builder stamp its run date would rewrite roughly 1,300 `join_note` strings
across `data/dataset.json` and would claim a fresh review for entries nobody re-read; the honest fix is a per-entry
review date, which is a schema change and not something to land unreviewed a few hours before the daily run. Filed
here as an open item for a work iteration.

## The CR-78.3 re-pin, re-derived

The pins moved again and the test that promised "no frontier model is tagged at this weight" was rewritten. This gate
recomputed the signal itself rather than reading the new comment:

- `kimi-k3::max` scores **3.047** (gap 1.725 + 0.3 × (17.39 − 12.98)), so it clears the light threshold of 3 by
  **0.047**, with an 80 % bootstrap interval of **[−12.87, +15.88]**.
- Because the family signal is carried by its best-evidenced configuration (CR-77.2), all three `kimi-k3` rows show the
  tag, including `::low`, whose own score is −5.03. That is the documented family rule, not a new defect.
- The live page discloses it: the tag pill carries `◔`, the tooltip reads *"The 80 % interval reaches below zero —
  treat this tag as uncertain"*, and the Composite line reads *"includes −3.0 for its Benchmaxxing signal (from 93.3;
  why, switch off in Options)"*.
- **The Composite effect is continuous, not a cliff.** `lib/composite.mjs` applies `composite − w·max(0, signal)`, so
  the board moved Kimi K3's penalty from about −1.5 to −3.0; the *tag* is the only thing that turned on at a threshold.

So nothing here is wrong, and the implementer neither fudged the tier nor hid the consequence — the tier is evidenced
by our own self-reported corpus, and its note understates rather than overstates it: 176 rows from **eight** labs
name Toolathlon at all, and **68** rows from six of them (Anthropic, Z.ai, Alibaba Qwen, MBZUAI, Moonshot AI, Meta)
name the Verified series by name, against the 41 the note claims.
But the promise Florian was shown has now been narrowed twice in two days as the corpus grew, and a frontier family
now carries a tag that rests on 0.047 points inside a ±14-point interval. **Florian's decision on re-running the null
simulation behind the 0.3 weight is the outstanding item, and this gate will not make it for him.**
