## Two defects found by this gate and fixed directly

### 1. Provenance defect: the August editions inherited June's task window

On /benchmarks the row of **ArXivMath 08/2026** read "Version 2026-08 · **tasks from 2026-06**" — false
published provenance. Cause: `lib/benchmark-matrix.mjs`'s `freshnessOf` is keyed by benchmark **family**, so
the new `::2026-08` identities inherited the June family's caveat (`data/benchmark-caveats.json` correctly
describes only the June edition). Same latent bug for BrokenArXiv 08/2026 (no task window shown yet, same
inheritance risk). Fix (`b672888`): `freshnessOf(key, caveats, version)` prefers a curated `family@version`
entry (the Benchmaxxing tier-table convention) before the family fallback; the two August editions carry their
own caveats quoting the pinned primary captures verbatim ("arXiv papers submitted in August 2026", from the
MathArena competitions endpoint's retained excerpt in the registry entry); the June family entry keeps serving
the June edition; the caveats test's `fieldText` matcher accepts the `family@version` form; a regression test
pins the precedence (June stays June, August says August, an uncurated version falls back). **Live after
deploy (`339c829`): both hosts, 1440 light + 390 dark — the ArXivMath 08/2026 row now reads "Version 2026-08 ·
tasks from 2026-08" and contains no "tasks from 2026-06"; BrokenArXiv 08/2026 reads "tasks from 2026-08".**
(14/14 + 14/14 checks.)
