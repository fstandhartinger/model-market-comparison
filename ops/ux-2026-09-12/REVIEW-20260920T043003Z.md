## What was wrong

`components/JevModelsV12.tsx` (CR-90, `f509927`) made the scoped view override the hero's decision count with
`tasksForScope(tasks.tasks, scope).length` — the number of **public** tasks. The public-task artifact ships 231 of the
benchmark's **534** decisions per system (`easy 72 · standard 96 · judge 146 · hard 220`, `data` re-read from
`ops/ux-2026-09-12/jevbench/v1.2.2/jevbench-v1.2-per-task.json`, whose `by_tier` counts sum to 534 per system). So:

| view | hero read (live, before this fix) | decisions the shown score is computed from |
|---|---:|---:|
| default, official `JevBench Score` | **231** | **534** |
| `?scope=easy-medium` | 120 | 168 (`easy 72 + standard 96`) |
| `?scope=easy` | 48 | 72 |

The default view is the worst of the three: it is the *official* score, and the page contradicted itself two panels
apart — the table's own tier headers read `Judge 146 dec.` and `Hard 220 dec.`, which alone exceed the 231 the hero
claimed. Before `f509927` the hero read 534. Under a scope the count was wrong in the other direction: Intelligence is
re-derived from the artifact's tier aggregates (all 168 easy+standard decisions), not from the public slice, so "120
decisions per system" understated the evidence behind the number next to it.

**The verifier had pinned the defect.** `ops/ux-2026-09-12/bin/verify-cr-90.mjs` asserted `/120 decisions per system/`
and `/48 decisions per system/` and had **no assertion at all** on the default view's eyebrow, which is why 66/66
passed on both hosts for three independent runs (codex-luna, opencode-kimi, and this gate's first run).

Fixed:
- `lib/jevbench-v12-scope.mjs` gains `scopeDecisions(tierCounts, id)` — the artifact's tier aggregate for the scope —
  and the component uses it. `lib/jevbench-v12-scope.d.mts` declares it.
- `test/jevbench-v12-tasks.test.mjs` pins 534 / `easy+standard` / `easy` and that each is strictly greater than the
  public-task count for the same scope, so counting public tasks here fails the suite.
- `verify-cr-90.mjs` now asserts `534 decisions per system` on the default view (and that `231 decisions` does *not*
  appear), still asserts the grid ships the 231 public outcomes, and expects 168 / 72 under the two scopes — 4 new
  checks per context, 74 per host.

## The modernised CR-87 verifier

`aba90e0` rewrote `verify-cr-87.mjs` from retired v1.1 selectors to v1.2 and passes 84/84 per host (re-run by this
gate). Two things it lost, recorded so they are a decision and not an accident:

- The **per-preset chart title** is no longer asserted. The old verifier pinned each preset's exact title
  ("… Emphasis on Accuracy (60:20:20)"); the new one checks only the re-ranking and the not-default state per preset,
  and the exact title only for the custom-URL case.
- The default title check went from an exact string to `/JevBench Score/` plus "not `not the official`".
- Preset orderings are now expected from the API's own `rank_under`, i.e. the same field the page reads, so for the
  five presets that check is self-consistency rather than an independent recomputation. The **custom**-weight case is
  still recomputed from the axis scores in the verifier (geometric mean with the URL's exponents), and
  `test/jevbench-v12-*.test.mjs` covers the weighting maths offline, so the formula is not unguarded — but the live
  preset check is weaker than the one it replaced.
