### Two notes the flipping gate must adjudicate

1. **Category-composite deviation with an overstated rationale.** The brief's literal CR-34.4 line asks for the
   index "to the taxonomy, category composites (Agentic & tool use) and the score pickers". Iteration 110
   deliberately did NOT make it a `cat_agentic` anchor and documented the reason as "only 15/20 featured families
   carry a value, so an anchor would delete the category score for most featured models". The mechanic describes
   `computeCategoryScores` (a model needs a result on EVERY anchor), so adding it would delete the Agentic
   category score for the 5 of 20 featured families without a value — **25 %, not "most"**. The decision may be
   defensible (a 75 %-covered anchor changing a published score's meaning for everyone is a real trade-off), but
   the recorded reason must describe the actual mechanics, and the deviation from the brief's literal wording
   should be called out for Florian in the next summary. This gate leaves the adjudication to a different engine.
2. **Default `/benchmarks` columns show "No result" for 4 of the top 5.** The default comparison columns are the
   `::max` display rows, while family-scope values live on the deterministic representative (`::high` for
   Fable/Astra/Opus/Sol). So the Agentic row — like Epoch ECI, Epoch Software ECI and both DesignArena boards in
   the same table — shows only Kimi K3's value (50.6) because Kimi's family representative happens to be its
   `::max` row. **This is pre-existing family-scope display behavior, not an iteration-110 defect** (ECI and
   DesignArena have rendered the same way), but it is a real product gap: a reader opening /benchmarks sees a
   nearly empty "Headline" row for exactly the marquee metric. Worth a work iteration that maps family-scope
   values onto the displayed columns or makes the default columns the representatives.
