## Observations beyond §6 (no new residual, recorded for completeness)

1. **The host allow-list excludes the legacy host.** A view/click/dismiss on
   `model-market-comparison.app.mintapis.com` is silently dropped by the endpoint (still 204).
   Consistent with §6.1's "the browser never contacts it" and with §6.4.3's floor-quality framing —
   an accuracy note, not a privacy gap. The banner nevertheless renders and dismisses correctly there.
2. `appliesTo()` matches by prefix, so subpaths (`/jev-models/v1.4.2`, a model page) also measure —
   as two fixed enum strings, exactly as §6.1 states. No drift.
3. Same-origin `sendBeacon` does attach the Auth.js session cookie; the route has no cookie code
   path and returns no `Set-Cookie`. §6.2's "nothing is joined" is therefore true in substance.
4. §6.4's three residuals (forwarded UA, unrecorded Umami retention, unauthenticated endpoint) are
   correctly stated and remain the record's own open items, not defects of this decision.

## Verdict

**ACCEPT.** The §6.2 walk of the §3 reopening conditions is accurate against the code: the one
literal trip ("client-side script/beacon") does not materialise into § 25 TDDDG storage or access,
no external provider is involved in substance, and every guard the record claims is present. The
no-banner branch of CR-67.6 standing is a defensible documented assessment for exactly this
configuration, with the same fallback (switch the beacon off) if a supervisory authority reads
"access" more broadly. D208 can be set **verified**.
