## Defect found by this gate, root-caused and fixed

**Live proof before the fix (`3683fbe`, mobile emulation 390×844, both themes, reproduce on canonical & legacy):**
verify-cr-2-2 **36/38** — "clicking a point adds its column at once and marks it" failed twice:
tapping the unselected GPT-5.6 Sol point toggled **Kimi K3 off** (6→4 columns, URL lost `kimi-k3::max`,
Sol never selected). Desktop light/dark passed.

**Root cause (measured):** on the phone chart, `gpt-5.6-sol::max` plots at svg(226, 865) and the selected
`kimi-k3::max` at svg(222.5, 857.5) — genuinely ~8 px apart. Their 28 px hit circles (`r={narrow ? 14 : 10}`)
overlap; selected points are painted *last* ("a chosen model is never hidden" comment in the code), so the
topmost hit area was Kimi K3's and every tap in the overlap landed on it. The only knob the user had —
tapping Sol's visible dot — could never select it. The same latent defect applied to desktop mouse clicks
(desktop just happened to have more room this time).

**Fix (`958f207`, minimal + tested):** `nearestHitId(pointsXY, coord, hitR)` in `lib/pick-chart.mjs` —
among all points whose hit area contains the pointer, the one whose **centre is nearest** wins; the svg now
handles clicks once (nearest-centre resolution) while each point keeps its keyboard handler (Enter/Space on
the focused point toggles exactly that point). Selected points still paint last for readability. Visual
behaviour unchanged elsewhere. Unit test: nearest-centre / tie-keeps-first / outside-null / empty-null.

**Re-verified live post-deploy:** cr-2-2 **38/38 both hosts**; the full `verify-cr-e2e` orchestrator at
`958f207`: unit **42/42** (the new test included), cr-1 **108/108**, cr-2-2 **38/38**, cr-presets **88/88**,
cr-5 **41/41**, cr-2-5-perf **28/28** — **ALL PASS per host**.
