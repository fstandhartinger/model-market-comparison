## What was wrong

**1. The public-task grid had six blank columns, and said one was blank.** CR-90.2's grid was pinned to the v1.2
public-task capture, which predates djev (v1.2.1) and the five systems CR-95 added (v1.2.2). The live page therefore
rendered **1,386** "no public outcome in the pinned artifact" cells — six of twenty-one columns, including
classifier.dev, the row the page now leads with — while the disclosure sentence named djev alone. A reader comparing
"which tasks each system got right" saw the #1 system as an empty column with no explanation.

The jevbench repo publishes a per-task artifact at tag v1.2.2 covering all 21 systems over the same 231 public tasks.
This gate re-pinned to it (`e418c7f`); the local copy is byte-identical to the public file
(`0a8146ea994807b943b663edb34c0fdc05d35c702f9dfc792006f0edf30cbc7b`, re-fetched from raw.githubusercontent.com). Before
swapping it in, the new artifact was checked against the score artifact: it validates under the existing fail-closed
validator, no system has unattempted items in the easy or standard tiers (so the difficulty-scope recompute is
unaffected), and every tier accuracy agrees with the published one. The disclosure sentence is now derived from the
data instead of naming a key, so a row added to a later score artifact can never be silently blank again; the unit
test asserts column coverage equals the scored systems, and the CR-90 verifier asserts no cell is left unavailable.

**2. The default radar pair was two nearly identical blues.** CR-95 gave "Service built on Jev" its own colour — a
second blue. The radars' default pair is Jev 1.13.0 vs the #1 row, which is now classifier.dev, so the first thing a
reader sees is two solid lines at `rgb(42, 122, 213)` and `rgb(84, 150, 214)` in light (`rgb(74, 149, 234)` and
`rgb(135, 190, 245)` in dark), distinguishable only by a 7 px marker shape. The component already had a treatment for
this case — when two picks share a type, B is dashed, mixed towards the text colour and square-marked — but it keyed on
the type, not on the colour. It now keys on the colour family (`5718dc0`), so Jev/jev-service pairs get the same
separation. The CR-94 verifier asserts the default pair is separated.
