# Explicit paid native v1.6 route

`python3 <installed-runtime>/v16_profiles.py inspect|measure|score <job-dir>` is a trusted host command, **not an agent tool**. Original autopickup default, v1.5 scoring/measurement adapter and pod driver bytes remain unchanged. The separate `official_score_v16.py`, `official_scoring_v16.py` and `pod_driver_v16.py` avoid invalidating unrelated accepted legacy pins. The shared pod_runner accepts a trusted callable supplying reviewed pins, stages a host-only text count config, and verifies returned count from the selected profile. Legacy calls retain defaults.

Prerequisites, issued by the actual custodian/root and independently reviewed; this implementation does not issue or authenticate grants beyond the already accepted host-state anchor:

- Fixed `<order>/review/V16-PROFILE-ADMISSION.json`: schema_version1, verdictACCEPTED, order_id, generation (lowercase letters/digits/hyphens), draw_release, rotation_tool_sha256, recipe_sha256, source_pins{model,code}, references{measurement,scoring,freeze,id_map}. Each reference is `{path: absolute host path, sha256: exact bytes}`.
- Fixed review/V16-PROFILE-REVIEW.json: verdictACCEPTED, reviewer_engineclaude, admission_sha256.
- Host order state `v16_profile_admission`: verdictACCEPTED, receipt_sha256, independent_review_sha256.
- Fresh exact review/GATE.json equal state.source_review_gate, CODE-REVIEW.md hash, trusted-runner manifest/files and official pins equal selected package. No old-gate reuse or invented PASS.

Measurement reference: existing schema_version1 code/inputs shape plus method`jevbench-v16`; inputs.jevbench.count1500 and exact items path/SHA; code key pod_drivers/pod_driver.py must bind installed pod_driver_v16.py bytes. Other code entries are pinned native source/record writer/adapters. Existing run_v15 record writer remains compatibility code: first-party driver manually loops against reviewed local endpoint inside network-none, so external runner selection is unavailable. Label-free count1500 is read from trusted text-config.json and validated before any real item dispatch.

Scoring reference: schema_version1 profiles.jevbench.version_prefix`v1.6.`; files named score_v16.py, score_v15.py, score_v15_headlineA.py, noul_method_v16.py, gold.jsonl, baseline.json, cost-basis.json. Each path/hash uses original official code snapshots or accepted fresh artifacts. baseline: method`jevbench-v16`, protocol`jevbench::v1.6`, noul_methodO1S, count1500, B1000, bootstrap_seed16, G_medfinite. This is the accepted cohort gap reference, never the entrant's isolated self-reference. cost-basis: exclude_opaque_ids (unique ids from exact newgold), rule, reference. Native row metadata has endpoint_kindgpu and frozen public base prices.

Measurement writes a **new** output generation directory `.local/state/fastlane-autopickup/measurements/<order>/<generation>/jevbench`, preserving old raw/receipts. It uses the **same original** order pod ledger and caps; no allocation/spend/reset authority is added. Wald therefore requires the root's separately reviewed scoped generation treatment before it can allocate. Score accepts only this exact generation's raw with matching pinned host receipt and SHA; raw from legacy results cannot enter. Automatic shared autopickup result adoption/mail/release is deliberately absent; the root must implement the reviewed explicit generation handoff or call host scoring/release after real receipt verification.

Runtime retirement check loads fixed official rotation source with accepted source SHA, uses fixed production ledger/reserve paths (ignores redirection env), matches id-map to exactS+P and rejects any currently retired sealed item before upload and after run. Root must own draw creation, published-ship ledger reconciliation, selection coverage, scale/method/reference decision and any fresh-run allocation authority. No original-cohort exception is assumed.

For three native paid models on a fresh cohort: official scorer can compute G_med over their full complete selfhosted rows; there is no five-model minimum for native rows. The five/six minimum belongs to external API equating. Compute and freeze the reference from all cohort members before official individual scoring. Any future API route requires its own full existing exposure/equating acceptance and is unsupported here.

Source checks use synthetic1500 rows only: isolated scorer/direct official scorer equality, CI/category preservation, common-cost denominator, duplicate coverage, O0 rejection, missing usage rejection, unaccepted host admission refusing before dispatch. Parent must obtain independent Claude review before install/activation.
