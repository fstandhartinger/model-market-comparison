### D249.2: an ignored worker can outlive a step that exits on SIGTERM

The existing timeout test covered a parent process that itself ignores SIGTERM. It missed a parent that exits on SIGTERM while a same-process-group worker ignores it. I reproduced that case with a disposable worker and saw it still running after `runStep` returned.

I added the failing regression first, then updated `ops/daily/step-process.mjs`: after a group leader exits, the grace escalation now checks live `/proc` process-group members against the captured PID/start-time identities before signalling. This keeps the PID-reuse guard while allowing SIGKILL to reach the original surviving worker. The focused test was 13/13 after the change. Because I implemented this correction in the review branch and it has not been deployed, D249.2 stays **open** pending a different reviewer and a post-deploy daily check.

Evidence: `/opt/benchmarkheaven/state/ux-evidence/review-20260929T072006Z/d2492-regression-red.log` (reproduces the defect), `/opt/benchmarkheaven/state/ux-evidence/review-20260929T072006Z/d2492-regression-final.log` (13/13), and the new case in `test/d249-2-step-process-group.test.mjs`.
