# JevBench v1.6 language diagnostics: proposed integration contract

CR-270 source preparation: the shared comparison component accepts an optional language artifact and keeps the same selected pair for all radars. Existing release pages supply no language artifact. Actual uc1.1 pool, method and aggregate artifacts remain pending independent owner review. All examples and tests are synthetic; they are not benchmark measurements.

Language diagnostics are a separate Choice-only supplement. The original1500-item primary headline and Capability/Composite method remain unchanged. Local supplement uses at least690 new sealed and690 public items across22 owner-confirmed languages; ar/da/zh-Hans require at least40 per split, others30. Actual frozen counts/descriptors/provenance supply the artifact. Hosted API supplements receive public items only and keep the dated original sealed score separately; no new sealed API subset is authorized. Earlier proposed supplementary300 API-sealed allocation is superseded.

The reviewed aggregator must emit actual stored-item metrics separately per language and split using the original group_stats basis: n, raw cc from cc_cell (equal mean over request types present), accuracy, n_by_type and low_n. This supplement is Choice-only; these values are not full Capability and cannot generate Capability/Composite/calibration/equating. Missing/incomplete runs remain unavailable rather than publishing partial averages. Non-OK decisions count wrong under the official scorer and still count in complete sample n. No golden labels or scorer semantics change here. Optional CI can be added only from a separately reviewed estimator; this minimal scaffold generates no CI.

Public artifact contains only whole-scope/method/pool hashes, aggregate cells/counts/dates/review-basis descriptors and unavailable reasons. It never contains item IDs/text/state/gold/answers/predictions/probability distributions/per-item hashes. The browser validator enforces exactly22 descriptor keys without inventing a real language roster. Synthetic fixtures use an explicit fixture marker rejected by default. Actual artifact import/pins/review method/date/count verification are release-owner steps, not scaffold authorization.

Default comparison uses the same public input-scope SHA for both systems. Local-only sealed comparison requires identical sealed input-scope SHA; API sealed remains unavailable and separately dated carried-base provenance. Different scope hashes never produce a common radar. No public/sealed/old/new pooled denominator or fabricated score. Raw negative cc stays visible in table and text, with coordinate clipping only for radar drawing. The full22-language table shows actual split/basis/n/expected_n/date/non-OK counts and unavailable reason. Optional selected-language radar shows at most8 axes. Existing topic/use-case radars, page menu/model list, headline, caps and all sections remain unchanged.

The optional comparison integration validates a supplied artifact, uses the existing A/B selection, and offers public or sealed views. Invalid artifacts produce an unavailable message; fixtures are rejected by default. Final adoption requires an explicit v1.6 release binding and independent real-method/artifact review. There is no page/version/artifact import, published synthetic score, deployment or benchmark run in this preparation.

The finalized source contract requires generated_utc (valid UTC timestamp) and rejects measured cell or carried-base dates later than that generation timestamp. Measured cells retain n_by_type exactly {choice:n} and low_n, matching the reviewed group_stats basis. Generation provenance and actual frozen input/receipt hashes still require release-owner verification; structural validation is not measurement approval.

Carried-base metadata includes its own revision, method_version, actual sample basis, positive safe integer n, measurement date and whole source artifact SHA. Honest older v1.5.5 n1624 may be carried with its original method explicitly identified; it is not described as the v1.6 n1500/600 method. Carried data is never converted into supplementary language cells. Real receipt/sample-basis verification belongs to the release owner. No score or confidence is reconstructed by this helper.

Exact prepared source files are lib/jevbench-languages-v16.mjs and .d.mts, components/JevLanguageComparisonV16.tsx, this method document and two synthetic test files. The component accepts languageComparisonView output without a separate shadow schema. It suppresses the radar unless at least three selected same-scope language cells are measured above the count floor for both systems; unavailable cells never produce an empty or zero polygon.
