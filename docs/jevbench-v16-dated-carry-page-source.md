# Dated carry page bridge — source candidate only

This new module family extends the current page without editing its frozen R2 implementation or the v1.5.5 route. It is not an adopted artifact, authentication service or release grant. The actual parent must authenticate public source artifacts, dates, measurement origins, source/runtime admission, and release permissions. SHA syntax and synthetic tests cannot establish those facts.

`projectJevV16RegistryWithCarry` accepts the original projection inputs plus a stored `carry` aggregate and `bindings.carry_diagnostics`. `loadJevV16PageWithCarry` additionally verifies that aggregate against the parent supplied expected hash before page assembly. The full 116-key catalogue and original cost, actual median, scorer-row, serving-lane, model-pin, public-origin and Capability checks remain unchanged. Current category/language bytes use the original contracts. Ranked historical rows must have a complete independent old-method profile; a missing row is a failure, never permission to remove it.

The carry aggregate schema is implemented in `jevbench-dated-carry-v16.mjs`. Its category artifact revision and source/result/taxonomy/cohort/projection hashes are separate from each model's original measurement revision, method, immutable pin, origin receipt and descriptor hash. Old category cells are {n, competence}; finite negative values are preserved. Original topic categories partition the full old pool; use-case membership may overlap. Partial topic row coverage remains partial. Original full-pool n/open/sealed descriptor counts are labelled as full-pool counts, not per-row category split counts. The row's original total n/open/sealed remains separately visible. No public/sealed category scores, failed counts, current equal-type averages or language cells are fabricated.

The date-evidence union supports an authentic calendar day with original measured-day wording and an explicitly unknown timezone, or an authentic UTC instant. It never fabricates midnight from a day, nor treats filesystem, build, publication or generation dates as measurement dates. The original frozen carry R3 full-UTC schema is unchanged. The future authenticated parent must validate source chronology, including same-day ordering that a day-only comparison cannot prove. Hash fields here bind admitted public bytes; they do not authenticate their creator independently.

The new page has a current/dated-old profile union. Historical topic and use-case panels use their own taxonomy, metric, minimum sample count, original version/date and raw cells. Missing spokes are unavailable; only radar geometry clips to 0–100. There is no cross-cohort overlay or conversion to current CategoryCell. Historical language is explicitly unavailable unless a separately reviewed exact-pin supplement contract is supplied. This candidate does not implement that extension. Current API A300+P300, local S1200+P300, and old cohorts remain UNEQUATED.

Page order and controls remain Capability, synchronized Capability-v-cost and Capability-v-adjusted-median plots with 3D toggle, stored Composite, compare both category panels and language, complete table, method/rotation/presets/stored What-If/history. Exact official precomputed scenario rows are required; no harmonic formula is recreated. Developer API/base-model scenario bars and existing disclosed historical per1000 estimates are preserved. Carry cost admission is still required; unknown cost or missing measured median cannot enter Capability caps. Scatter coordinates and derived traffic/score bar widths are rounded to three decimals for deterministic SSR.

Only the future authenticated server parent supplies adopted PUBLIC bytes and trusted expected hashes. The server component is not installed in a route, and performs no filesystem/network fallback. Default production APIs reject fixture=true. Actual original dates, profile provenance, admissible old cohort joins and release adoption remain required; this source has not produced any real data or conferred approval on the held old carry helper or source adapter.

The R2 correction persists presentation controls in the URL: `costcap` and `latcap` accept factors 1–10 or `off`, and `jevscenario` selects only an existing stored scenario identifier. Missing, malformed, duplicate or unknown values independently fall back to the official 2× caps and official stored scenario. Fractional factors remain exact; arbitrary URL weights never enter the scorer. Official defaults serialize by removing the owned parameters. Unrelated query parameters, the fragment and existing history state remain intact.

The server boundary accepts `initialSearch` and passes the same value to the client for SSR and initial hydration. There is no render-time browser access. After mounting, the client reads the actual browser URL, listens for `popstate`, and writes control changes with `replaceState`. The effect removes its listener on cleanup. History navigation changes presentation only; it neither authenticates new artifacts nor alters stored rankings, costs or provenance. The historical table also displays the original measurement-date precision and timezone separately. The original frozen current-only page R2 and dated-carry R1 packets remain unchanged.
