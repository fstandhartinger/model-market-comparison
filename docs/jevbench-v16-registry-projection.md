# Final JevBench v1.6 registry projection — source candidate

`projectJevV16Registry` is a separate pure public-aggregate interface. It is not wired to a page, loader, route, scorer, current data or release. The existing v1.5 views and optional category/language panels remain unchanged. No actual release artifact is adopted by these tests.

The input contains stored UTF8 JSON and exact SHA256 descriptors for the registry-builder output, final scorer artifact, measurement bindings, current category aggregate, and language supplement, plus original public measurement provenance receipts. The helper verifies bytes before a duplicate-preserving JSON parse, rejecting unused numeric overflow, unpaired Unicode and conflicting fields. Authenticating those expected hashes and actual source/runtime/release approval remains the parent's responsibility. Its output deliberately has `approval: null`.

The accepted registry builder's115 historic listings and Fastino remain116 catalogue entries. Its113 explicit scorer registrations retain their declared support; the three missing metadata registrations stay null. No ownership, support, model size, date or current score is inferred. Old cost fields remain separately disclosed historical estimates. Unmeasured rows have null score/axes/current cost/latency/diagnostics. Listed current/carry rows keep their own measurement provenance and actual explicit serving metadata.

The final scorer artifact needs a new `projection` metadata contract containing the frozen reference cost and adjusted median latency, official2x caps, generator day, exact registry/category/language source hashes, scorer SHA/method version and category provenance. A nonfixture reference is exactly `jev-1.13.0`. Its source hash must resolve to supplied verified stored reference-origin bytes with matching key/cost/median/caps and explicit version/pin/measurement provenance; arbitrary catalogue keys or unbound numbers refuse. Unknown original pin/date remain explicitly null. These caps are never recalculated from a filtered roster. Its existing uncapped `board.capability` is not used for the headline. Capability is the arithmetic mean of the stored Intelligence/Calibration, while headline eligibility independently requires ranked completeness, an admitted scoring price and measured median inside both frozen caps. The composite retains its stored score and own ordering. A finite cost with `cost_rank_eligible:false` cannot become eligible. Measured/estimated/mixed kinds and bases remain visible; estimated eligibility requires an explicit cost-admission binding. Unpriced operational estimates never rank.

The separate measurement manifest binds the exact final release hash/public source hash and each aggregate row's canonical SHA to its original measurement revision/method/date/model version/model pin/scorer/cohort/serving identity and explicit cost eligibility. Each origin is independently stored/hash-bound public metadata; conflicting or missing origin/date/version/pin/serving/source refuses. A current measurement requires a genuine calendar day, full1500 self-hosted or600 API denominator and300 public items; a carry retains its older method and unknown date when unknown. Calendar dates are not populated from publication/build/mtime.

Every ranked row additionally needs a per-key diagnostic binding of the SAME model version/pin and main measurement date to actual stored category/language artifact hashes, four category pins and language pool/method pins. Category rows must match the current cohort/date/lane; language supplement cells retain their own measurement dates. Missing coverage refuses the final projection rather than borrowing another model or creating values. Raw category competence stays negative where stored; empty and low-n cells retain their own availability/counts. API A300+P300 and local S1200+P300 category radars are unequated one-system profiles, not a same-cohort comparison. No category estimate is produced.

A ranked historical carry currently refuses: no accepted dated-carry category contract exists in this source graph. Such a row can remain listed with its older method/date/raw values and unavailable current diagnostics. A future independently reviewed carry panel/aggregate contract is required before it can join final ranked coverage. The unreviewed category-carry candidate is not read or adopted here. This is an honest release integration gate, not a change to carry policy or automatic exclusion from the eventual release.

Serving price, developer API list scenarios, and base-model reference scenarios are distinct bars. Scenarios have no current rank/score/axes and never replace the measured served cost or GPU latency. Historic alternative axes/scores/views are excluded even if supplied. Self-hosted clef/flash would therefore retain their current GPU latency; an API list price alone cannot assert hosted performance. The helper does not recalculate composite at another price.
