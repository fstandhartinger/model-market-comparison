# Optional current JevBench v1.6 category profiles

`JevCompareV15` accepts an optional `currentCategories` aggregate. It follows the exact current `category-aggregates` output of `aggregate_categories.py`, separate from the existing historic `categories` prop and language supplement. No release page or loader supplies it yet. This source preparation changes no artifact, roster, route, headline, table, measurement or release version.

The helper checks the revision, exact projection, four provenance hash fields, real measurement dates, original cohort denominators, per-type counts, failures, empty/low-count cells and coverage predicate. This is structural validation, not artifact admission or proof that hashes bind actual sources. An independently reviewed runtime must bind the official scorer, frozen original draw, labels and native label-runtime sources before a release adopts actual aggregates. Arbitrary values and unknown per-item fields are rejected.

Each selected system gets its own topic and use-case radar and table. Self-hosted systems use S1200+P300; APIs use A300+P300. Raw competence is unequated. The panel explicitly says these separate profiles are not a same-scope comparison or Capability Scores. Each profile shows its own lane, measurement date and public/sealed counts. Five supported categories are required for a radar; empty and low-count cells remain in tables but are excluded from plots. Negative competence remains in labels/tables; coordinates alone clip to 0–100. Failures stay in the denominator.

A selected historic row without current aggregates is unavailable. No v1.5 category values or dates are substituted. The category-carry candidate remains parent-held and unreviewed: this component has no carry contract, import or fallback. Any future dated carry panel needs separately reviewed artifact/provenance and old-method semantics; it must not blend old and current category profiles.

The fixtures are public synthetic metadata with fictional pins and year-2000 dates. SSR checks exercise the actual component, helper, selector state and comparison figures; only the picker display is stubbed. Compatibility evidence also invokes the pinned accepted aggregation source with synthetic metadata and stub statistics; it is schema evidence, not a real scorer/model measurement. No protected items, real category labels, inference, browser/provider calls, artifacts or runtime admission are involved.
