# Fresh native v1.6.2 publication contract

This implementation adds a conditional version page and API. It leaves the current full `/jev-models` board, its data, and earlier versions in place. It does not publish an empty candidate or replace the full catalogue with a smaller cohort.

No v1.6.2 data ships with this code. Before the publication manifest exists, the new page and API return 404 and the version navigation omits the tab. An invalid manifest or mismatched evidence is an error, not a fallback to another release's scores.

The official evaluator builds these aggregate-only files under `data/raw/benchmarks/jevbench/v1.6/`:

- `jevbench-v1.6.2-results.json`: ordinary v1.6 system aggregates, revision `v1.6.2`, status `published`, provisional `false`, run_kind `paid-fast-lane`. Every system is a native self-hosted row with 1,500 observations and measured_in `v1.6.2`. S=1200, P=300, selfhosted_input=1500. O1S, bootstrap B=1000/bootstrap_seed=16/g_med_fixed=true. v16.draw_release and v16.freeze_manifest_sha256 bind the fresh draw. Historical systems must not enter this file or its field median. Board score reproduction uses the existing official axes/composite validator.
- `jevbench-v1.6.2-categories.json`: observed category aggregates, revision `v1.6.2`, provisional `false`; topics, usecases, languages and system cells on this exact cohort. source_results_sha256 retains the established scoring-source convention; results_sha256 additionally binds the actual public result bytes. draw_release must match the proof. Every nonempty published category needs an observed cell for every cohort system. A zero-population category may have no cell. No estimated radar values or historical supplement cells.
- `jevbench-v1.6.2-proof.json`: schema_version=1, revision `v1.6.2`, method `jevbench::v1.6`, noul_method `O1S`, bootstrap `{B:1000,seed:16}`, draw_release, freeze_manifest_sha256, seed_commitment_sha256, source_sha256. `systems` contains each cohort key once, with rows=1500, admission=`ACCEPTED`, admission_sha256, raw_sha256, source_review_sha256, model_commit, code_commit and completed_at. Only hashes and identities are public; input text, gold, individual predictions and the seed value are excluded. `field_median` contains `{G_med,members:[{key,gap}]}` for exactly the ranked native cohort. Each gap must match that system's stored aggregate `intelligence.gap`; the median must reproduce G_med. A null/planning baseline cannot publish.
- `jevbench-v1.6.2-history.json`: byte-for-byte snapshot of the public v1.6.1 result artifact being retained, including all original model metadata and scores. A snapshot prevents later v1.6.1 addenda from silently changing this version's history. Its hash is historical_results_sha256 below. The source pins the exact unmodified published v1.6.1 bytes (SHA-256 `5cd8c1332226ea9c179883d2285c0d8b8cc593ae38f2645197364a7ddd9c83c1`) from repository commit `4a763f2696339cca778a6811933417efc720b141`. A valid-looking replacement is rejected. The snapshot must contain no v1.6.2 rows. Separately dated carry is snapshotted in `jevbench-v1.6.2-history-carry.json`, with source-pinned SHA-256 `334e851944e92383ab3071e52b3012040c7023d0fe236395953169ebee8f0459`. It is validated against the snapshot’s measured keys and the frozen v1.5.7 source, never against a later v1.6.1 addendum. A carry row may replace only its explicit historical not-measured placeholder; duplicate measured/carry keys are errors. Historical values do not enter new ranking, category cells or G_med.
- `jevbench-v1.6.2-publication.json`: schema_version=1, revision `v1.6.2`, status `published`, provisional=false, historical_revision `v1.6.1`, historical_results_sha256, historical_carry_sha256, and `review:{verdict:'PASS',engine:'claude',receipt_sha256:<actual independent release review>}`. `files` has results/categories/proof/history/history-carry entries, each `{path:<exact filename above>,sha256:<actual bytes hash>}`. This is the activation artifact and must be written last, after actual independent release acceptance. A source preparation review is not release acceptance.

The new page reuses the complete board components: capability, speed/cost charts, composite, comparison and both category radars, full data table, method/presets/What-If, and history. It passes the new category artifact directly rather than selecting globally imported old cells. A separate historical catalogue retains every prior measured, unmeasured and carried row with original values and dates. Wrappers/subsidised entries remain outside native ranking and are placed last in the historical catalogue.

The publication loader proves shape, byte bindings and internal aggregate consistency; it cannot authenticate a reviewer's identity or private execution receipts by itself. The owner must supply genuine accepted receipts, run the normal review/merge queue and verify deployed results on both hosts. No new default current-release pointer or customer emails are part of this change.

Navigation on every version uses the same availability check. An absent or invalid fresh bundle omits its tab; invalid evidence emits a generic diagnostic without paths or private content. Existing boards remain available. Direct requests to v1.6.2 still fail closed on invalid evidence.

All six bundle files (manifest, results, categories, proof, history and history-carry) apply the existing explicit djev/djev-thinking raw-text exclusion and private-name token exclusion. Fresh categories require nonempty lane_note, metric and labelling, string rules, exact native cohort lane joins, and valid descriptor n/open/sealed/low_n values. Language totals must be exactly 300 public plus 1,200 sealed. Historical live_category_cells, supplement, language_cells and unavailable overlays are rejected; zero-population categories may remain unplotted without invented values.

Historical system keys are public identifiers already present in the published results and prior board markup; rendering them in row attributes is intentional. Snapshot bytes preserve their original metadata. Tests exercise real bundle files, source pins, missing/partial/invalid evidence, raw private exclusions, wrapper/subsidised cohort rows, direct API/page absence, and the real server-page frame with chart/client boundaries stubbed. The page’s historical table and loader are not stubbed. Full chart browser behavior and production build remain normal queue checks.
